# Архитектура

## Принципы

- **Сервер решает всё.** Клиент присылает только намерения («поставить башню X в точку Z»);
  деньги, урон, волны, награды, сохранение считаются на сервере. Клиент рисует и анимирует.
- **Один цикл на всё.** `MatchService` обновляет все матчи из одного `Heartbeat`, внутри матча —
  фиксированный шаг 20 Гц (`Game.Match.TickRate`). Нет `while`-циклов на каждую башню или врага.
- **Без физики в бою.** Враги движутся как «дистанция по маршруту», снаряды — отложенные попадания
  (`Match:Schedule`), а визуал снарядов строит клиент. Сервер не создаёт деталь на каждый выстрел.
- **Общая логика.** Проверка размещения (`Logic/Placement`), выбор цели (`Logic/Targeting`),
  расчёт урона (`Logic/Combat`) и раскладка карт (`Logic/MapLayout`) лежат в `Shared` —
  подсказка у призрака на клиенте совпадает с решением сервера.

## Сервер (`src/server`)

| Модуль | Ответственность |
|---|---|

| `Services/DataService` | DataStore `R6TD_Players_v1`: UpdateAsync, замок сессии, автосохранение, BindToClose, повторы; режим памяти с честным предупреждением |

| `Services/ShopService` | магазин башен за гемы, набор на матч (до 5 башен, только в лобби), настройки игрока; авто-скип сразу применяется к матчу |
| `Services/ElevatorService` | 4 независимые группы: Empty → Waiting → Starting → InMatch, лидер, карта, вместимость, готовность |

| `Match/Match` | состояние одного матча: игроки, деньги, база, голосования, снимок для клиентов, пакет эффектов |

| `Match/EnemySystem` | появление, движение, способности (регенерация, лечение, топот, призыв, ярость), смерть, утечка |
| `Match/TowerSystem` | установка, улучшение, продажа, приоритет, оглушение башен, шаг атак |
| `Match/Attacks` | 8 видов атаки: меч, стрела, пистолет, пулемёт, снайпер, яд, топор, когти |
| `Match/MapBuilder` | геометрия карты по `Config/Maps` и `Logic/MapLayout`; в конце `Visual/Studs` переводит карту в классический студ-стиль |

### Матч в мире

Каждый матч строится в своём слоте: `Game.Match.SlotOrigin + (слот − 1) × 400` по оси X,
до 8 матчей одновременно. Папка `Workspace.ActiveMatches.Match_<id>` содержит карту,
`Enemies` и `Towers`. Матчи разных групп не пересекаются.

### Жизненный цикл

1. Лифт переходит в Starting (группа заполнена / все готовы / лидер нажал «Старт» / истёк таймер).
2. Через 5 секунд состав фиксируется, `MatchService:Create` строит карту и переносит игроков.
3. Подготовка 20 с (можно пропустить голосованием), затем 20 волн. Между волнами 7 с. У базы 3 жизни: каждый прорвавшийся враг отнимает одну.
4. Конец матча → награды (гемы, опыт, статистика) → сохранение → экран итогов.
5. Игрок нажимает «В лобби» или через 30 с возвращается автоматически.
6. Когда в матче никого нет — `Match:Destroy` удаляет карту, врагов, башни и отложенные задачи, слот освобождается.

Отключение игрока не ломает матч: его отметка `Connected = false`, голоса снимаются, башни продолжают работать.
Если вышли все — матч закрывается сразу.

## Правила боя (`Logic/Combat`)

- Броня — плоское снижение урона за удар, `Pierce` игнорирует долю брони, минимум 20 % урона.
- Щит поглощает урон первым.
- Яд игнорирует броню и щит. На враге одновременно один яд: берётся максимум DPS,
  длительность обновляется, но не накапливается сверх длительности последнего попадания.
- Оглушение: не действует на элиту и боссов, после оглушения 1,5 с иммунитета (нет вечного станлока).
- Замедление: действует сильнейшее, не суммируется.
- Скрытные враги видны только башням с `Detect`.
- Награда за убийство выдаётся строго один раз (`Enemy.Dead`).

## Сеть (`src/shared/Net.luau`)

- `Action` (RemoteFunction): `ElevatorSetMap`, `ElevatorSetCapacity`, `ElevatorReady`, `ElevatorLeave`,
  `ElevatorStart`, `PlaceTower`, `UpgradeTower`, `SellTower`, `SetPriority`, `VoteSpeed`, `VoteSkip`,
  `ReturnToLobby`, `RequestState`, `BuyTower`, `EquipTower`, `UnequipTower`, `SetSetting`. Ответ — `{ ok, message, data }`.
- События сервер → клиент: `LobbyState`, `MatchState` (снимок матча до 10 раз/с при изменениях,
  минимум 5 раз/с), `MatchFx` (пачка визуальных событий за тик), `MatchEnded`, `Profile`, `Notify`.
- Все удалённые объекты создаются при старте сервера (`NetService:Init`), клиент ждёт их через `WaitForChild`.
- Движение врагов: у модели атрибуты `Dist0`, `Time0`, `Speed`; клиент экстраполирует позицию
  по маршруту, сервер переотправляет атрибуты при смене скорости или раз в 1,5 с.

## Модели R6 (`src/shared/Visual`)

- `R6.Build` — риг с классическими размерами (торс 2×2×1, конечности 1×2×1, голова 2×1×1 с мешем)
  и стандартными C0/C1. Если есть `ReplicatedStorage.Assets.R6Dummy` — клонируется он (без скриптов, одежды, аксессуаров).
- Позы задаются запеканием в C0 (`R6.BakePose`), оружие крепится Motor6D к руке с расчётом хвата (`R6.Grip`).
- `TowerModel` — 8 башен, снаряжение меняется по уровню (Tier 1–3). `EnemyModel` — враги с цветами, шлемами, щитами, оружием.

## Сохранение

Профиль (`Logic/Profile`, версия 2): гемы, уровень, опыт, статистика, лучшая волна по картам,
купленные башни (`owned`), набор на матч (`loadout`) и настройки (`settings`). Профили версии 1
переносятся автоматически: прогресс сохраняется, из башен остаётся стартовый мечник.
Покупка сохраняется в DataStore сразу.

### Авто-скип

`Match:CheckAutoSkip` на каждом шаге: если фаза — подготовка или перерыв и **каждый** игрок либо включил
авто-скип, либо проголосовал за пропуск, ожидание заканчивается (не раньше 1,5 с после начала фазы).
В подготовке игрок с авто-скипом считается готовым только после установки первой башни.
Набор башен игрока фиксируется при старте матча, и сервер не даёт поставить башню вне набора.
Состояние матча не сохраняется. Загрузка — 5 попыток; при неудаче на живом сервере игрок кикается
с просьбой перезайти (чтобы не затереть прогресс пустым профилем). В Studio без доступа к API —
режим памяти и предупреждение в интерфейсе; экран итогов пишет «Прогресс сохранён» только когда это правда.
